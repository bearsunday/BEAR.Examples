# Agent Notes

## Environment

- This project requires PHP 8.5. On this machine, use `zsh -ic 'sphp85; <command>'` for Composer/PHP commands that need the Homebrew PHP 8.5 runtime, or prefix `PATH` with `/opt/homebrew/opt/php@8.5/bin`.
- The namespace root is `MyVendor\Cms\`; Composer maps it to `src/` and maps the same namespace to `tests/` for dev/test fakes.
- The checkout may be detached. Create a feature branch from `1.x` before committing unless the user asks otherwise.

## Project Shape

- This is a BEAR.Sunday reference CMS: HAL+JSON App resource API plus read-only Qiq/Page HTML. Admin write UI and JavaScript frontend are not built yet.
- Canonical implementation rules live in `docs/conventions.md`; read it before changing resource, query, SQL, schema, or fake-data behavior.
- Useful orientation docs:
  - `README.md` for setup and the reading order.
  - `docs/architecture.md` for the BDR layout and context composition.
  - `docs/resources.md` for URI and response shapes.
  - `var/alps/profile.json` and `docs/alps.md` for semantic source-of-truth changes.
  - `tests/Fake/FakeSqlQuery.php` for how `#[DbQuery]` dispatch is faked.

## Runtime Contexts

- App contexts:
  - `hal-api-app` and `cli-hal-api-app` use the real database.
  - `fake-hal-api-app` uses `tests/Fake/FakeSqlQuery.php` and requires no DB.
  - `test-hal-api-app` is used by PHPUnit and composes the fake module.
  - `slow-fake-hal-api-app` overlays `src/Module/SlowModule.php` on `fake-hal-api-app` to add a 150ms delay to the three embedded resources; demo-only.
  - Parallel `#[Embed]` execution is enabled at the entrypoint, not via a context prefix. Use `bin/async.php` instead of `bin/app.php`; the same `AppModule` runs unchanged. Requires PHP ZTS + `ext-parallel` (Docker).
- HTML (Page/Qiq) contexts:
  - `html-hal-app` and `cli-html-hal-app` install `HtmlModule` over the real database.
  - `html-test-hal-api-app` composes `TestModule` and `HtmlModule` so Page tests render against `FakeSqlQuery`.
- If module bindings change, clear the DI cache for every context that was used: `rm -rf var/tmp/*-hal-app var/tmp/*-hal-api-app`.

## Development Commands

- Install dependencies: `zsh -ic 'sphp85; composer install'`
- Run the default no-DB test suite: `zsh -ic 'sphp85; vendor/bin/phpunit'`
- Run coding standards: `zsh -ic 'sphp85; composer cs'`
- Run static analysis: `zsh -ic 'sphp85; composer sa'`
- Run the full quality gate: `zsh -ic 'sphp85; composer tests'`
- Regenerate deterministic fake data and schemas: `zsh -ic 'sphp85; composer semantic'`
- Quick SQLite setup for real-DB trials: `zsh -ic 'sphp85; composer sqlite:up'`
- Serve Qiq/Page HTML: `zsh -ic 'sphp85; composer serve'` (`http://127.0.0.1:8081`)
- Serve the HAL JSON API: `zsh -ic 'sphp85; composer serve:api'` (`http://127.0.0.1:8080`)

## Coding Rules

- Keep the Read/Write split: `<Entity>QueryInterface` for reads and `<Entity>CommandInterface` for writes, both in `src/Query/`.
- Query methods use `item`, `by<NaturalKey>`, and `list`/`list<Variant>` naming. Command methods use imperative verbs such as `add`, `update`, `delete`, `clear`, and `link`.
- SQL files live in `var/db/sql/` and match method names, for example `article_item.sql`, `article_by_slug.sql`, and `article_tag_link.sql`.
- Entity classes are `final readonly` with public properties. `SELECT` column order must match the entity constructor argument order.
- After inserts, recover the new entity by natural key (`bySlug`, `byEmail`, `byFilename`), not `lastInsertId`.
- Resource dependencies use queryable nouns for reads (`$article`) and `Cmd` suffixes for writes (`$articleCmd`).
- In resources with `#[Embed]`, preserve embedded request slots by adding scalar fields with `$this->body += [...]`. Without embeds, assign a literal `$this->body = [...]`.
- Use scalar resource parameters for short flat inputs. Use `src/Input/*Input.php` DTOs when the request has many fields, tri-state semantics, or a coherent named shape.
- Keep `src/Resource/App/Variations/` to the existing three comparison-only article resources; do not add another variation.
- Do not throw generic runtime exceptions from `src/`; add a domain exception under `src/Exception/` when a thrown exception is needed. Not-found reads should set 404 bodies instead of throwing.

## Generated And Data Files

- Fake data is in `var/fake/*.json` and is deterministic.
- Response schemas live in `var/json_schema/*.json`; input validation schemas live in `var/json_validate/<entity>_<verb>.json`.
- ALPS changes should start from `var/alps/profile.json`, then update generated docs/schemas as needed.
- API docs are generated by `composer doc`; CLI commands are regenerated by `composer cli`.

## Tests

- Default PHPUnit tests are hermetic and run without a database.
- Integration tests under `tests/Integration/` target MySQL and skip when MySQL is unavailable.
- Prefer internal fake classes from `tests/Fake/` over mocks.
- When changing resource behavior, add or update focused tests in `tests/Resource/`, `tests/Hypermedia/`, `tests/Entity/`, or `tests/Smoke/` to match the behavior touched.

## GitHub And Commit Notes

- Use English commit messages.
- Keep commits scoped to one logical phase.
- Do not add `codex`, `[codex]`, or other Codex branding to PR, issue, or commit titles.
